# 开发记录

## 2026-10-10：回退为纯本地运行版本

- 根据当前阶段需求，移除 AWS SDK、CDK、AgentCore、S3、DynamoDB、API Gateway、Step Functions 和云端轮询工作流。
- Web 固定使用本地连续视觉任务；作品展示改为读取 `public/showcase` 静态产物，数据库/S3 入口同步移除。
- 本地分析、名单校验、轨迹身份确认、统计面板和问答保留，且无需 AWS 凭证即可运行和测试。

## 2026-10-10：视觉质量、媒体缓存与数据输入边界

- 本地视觉增加可配置的球员/篮球置信度阈值、检测类别和比分牌 OCR 间隔，并将帧覆盖率、篮球覆盖率、平均检测置信度和轨迹数量写入 `tracking.quality`。
- 当使用 COCO 通用模型、轨迹数量明显异常或篮球覆盖率过低时，结果会明确写入 warning；前端不会把过期篮球位置当作当前帧。
- 云端媒体桶增加 CloudFront OAC 缓存行为；内容指纹视频设置长期 immutable 缓存，并支持通过 `MEDIA_BASE_URL` 返回同源 CloudFront 播放地址，未配置时仍回退到 S3 预签名 URL。
- 浏览器播放使用 `preload="metadata"`，本地/演示分析不再在缺少 xFG、引力和胜负影响时填充固定演示指标；CSV 解析支持引号、逗号和数值类型。
- AgentCore 输入限制为可审计的 JSON 记录或 CSV 行，并把连续视觉质量摘要一并提供给模型；输出事件还会按原始资料中实际存在的指标字段过滤，缺少依据时清空指标事件和解说。
- DynamoDB Jobs 增加 `status-updatedAt-index` 与 `inputDigest-index`；作品列表和视频查重使用 Query，避免随着任务量增长执行全表 Scan。

## 2026-10-10：线上连续视觉基线

- Step Functions 在 AgentCore 前新增 Amazon Rekognition Video 异步标签检测，并对 Person 实例框执行跨时间 IoU 关联。
- 新增 `ContinuousVisionWorker` Lambda，轮询完整视频任务并将结果转换为共享 `TrackingResult v1`。
- 连续结果写入 S3 `jobs/{jobId}/tracking.json`，DynamoDB 仅保存 `trackingKey` 与提供方，避免大对象超限。
- AgentCore 读取压缩轨迹摘要，同时保留 6 张关键帧作为语义证据；跟踪失败时自动回退并写入警告。
- 当前线上模型不自动命名球员，也不声称能可靠区分裁判；下一阶段用 SageMaker 篮球专用模型替换同一接口。
- 实测赛事权限边界拒绝 `StartPersonTracking`，因此没有依赖该接口；`StartLabelDetection/GetLabelDetection` 已通过账号验证。
- 用现有 21.5 秒、83.9 MB、1080p/59.94 FPS 视频完成真实冒烟测试；Rekognition 成功返回约每 0.5 秒的 Person 实例框。等待时间达到分钟级，因此前端轮询上限从 12 分钟调整为 55 分钟。
- Person 标签会包含观众，适配器按框尺寸、画面区域、长宽比和跨帧持续性过滤，并把每个时间点限制为最多 14 个候选。Basketball/Ball 标签仅在部分时间点返回实例框；没有框时不生成虚假的篮球坐标。
- 最终部署 Lambda 使用同一真实结果转换出 44 个时间点（0–21.5 秒）、54 条有效轨迹，其中 31 条至少持续 5 个时间点，并检测到 11 个带框的篮球时间点；验证用 DynamoDB/S3 记录随后清理。

## 2026-10-10 - 统一比赛资料入口

- 将“深度数据”和“比赛名单”合并为单一“比赛资料”选择项，支持 JSON / CSV。
- 云端 Agent 统一读取、分类并将资料随任务存入 S3；用户无需预先指定数据类型。
- 本地视觉会自动识别独立名单 JSON 或组合资料中的 `roster` 字段，并用于身份约束。

## 2026-10-10 - S3 数据资产库

- 将原“新建分析”导航拆为“数据库”和“素材导入”，与作品展示形成三个独立入口。
- 新增只读 `GET /storage` 接口，分页读取赛事 S3 桶并按视频、资料、关键帧、分析结果分类。
- 数据库页面提供对象数、容量、分类统计、搜索、筛选和手动刷新；不提供删除或下载权限。

## 2026-10-10 - 动态作品库与视频去重

- 作品展示改为读取 DynamoDB 已完成任务，按完成时间倒序列出，并可自由切换视频和分析结果。
- 浏览器分块计算整段视频 SHA-256；创建任务前由 API 查重，重复时返回原任务并提供“查看已有作品”入口。
- API 创建任务时再次校验，避免绕过前端；新视频以指纹作为 S3 对象键，极端并发下也不会生成两个视频对象。
- 旧任务按文件名、时长、S3 对象大小兼容查重，并在作品列表中折叠重复记录。

## 2026-10-10 - 取消外接设备方案

- 根据主办方确认，项目成果不能外接设备；移除设备中心、设备结果页和 ESP32 接入预留。
- 删除 `DeviceEvent` 协议和外设接入文档，架构不再包含设备 WebSocket 通道。
- 保留与网页播放和最终成片有关的解说文本能力。

## 2026-10-10 - 云端视频分片上传

- 超过 16 MiB 的视频改用 S3 Multipart Upload，默认约 8 MiB 一片、浏览器 4 路并发。
- 单个分片失败最多重试 3 次，只重传失败部分；全部分片完成后由 API 合并，再启动 AgentCore。
- 上传进度按所有分片的真实字节数计算；失败时主动中止上传，S3 一天后自动清理遗漏的未完成分片。
- 小于 16 MiB 的视频保留单文件上传，旧版前端请求仍可兼容。

## 2026-10-10 - 比赛身份确认与官方数据防误填

- 新增 `MatchEvidence`、`MatchCandidate`、`MatchResolution` 契约，明确 confirmed / ambiguous / unconfirmed 三种状态。
- 本地视觉服务对转播画面顶部做可选比分牌 OCR，输出带时间戳的 `videoEvidence`；OCR 不直接修改比赛统计。
- Web 新增候选比赛提取和确定性匹配器，使用球队、球员、号码、比分多证据打分；证据不足时保持未确认并将原因写入分析警告。
- 后续接入 AWS 时，将本地候选目录适配器替换为官方比赛检索工具，确认后再读取 Box Score / Play-by-Play。

## 2026-10-10 - 篮球比赛数据仪表盘

- 新增 `GameStatsTimeline` 与两队快照契约，支持进攻、防守、效率、比赛状态四类 Tab。
- 展示页通过 `stats.json` 按视频时间读取 Box Score / Play-by-Play 快照；缺失字段隐藏，不由视觉模型推断。
